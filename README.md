## Данные и модель

В [data](data) находятся 10 CSV по 1000 строк. Переносы строк внутри описаний товаров обрабатываются CSV-парсером.

Одна строка исходного файла считается одной продажей. Номер `id` повторяется между файлами. Ключ продажи состоит из имени файла и номера строки `id`. Поля `sale_customer_id`, `sale_seller_id` и `sale_product_id` не используются как уникальные ключи справочников.

Сумма продажи берется из `sale_total_price`. Она не заменяется произведением цены на количество, так как эти значения в учебных данных расходятся.

Контрольные значения находятся в [expected.json](expected.json).

| Показатель | Значение |
|---|---:|
| Продажи | 10000 |
| Количество товара | 54623 |
| Сумма продаж | 2529852.12 |

В звезде используются измерения покупателей, продавцов, товаров, магазинов, поставщиков и дат. В факте хранятся ключи измерений, количество и сумма продажи.

Ключ измерения строится по полному набору его атрибутов. Так разные версии характеристик не перезаписывают друг друга. Это учебная модель версий, без восстановления истории реальных изменений.

## Реализация

[Scripts/produce.py](Scripts/produce.py) преобразует CSV в JSON и отправляет по одному сообщению на продажу в топик `sales`.

[src/main/java/mai/SalesJob.java](src/main/java/mai/SalesJob.java) читает топик через `KafkaSource`, разбирает JSON и записывает измерения и факт в PostgreSQL. Для каждой продажи используется одна транзакция. При ошибке запись откатывается, ошибка передается Flink.

Доставка имеет семантику at-least-once. Checkpoint сохраняет позицию Kafka. Повторное сообщение не создает новую продажу благодаря первичному ключу `sale_key` и `ON CONFLICT DO NOTHING`. Это не распределенная exactly-once транзакция между Kafka и PostgreSQL.

[sql/01_start.sql](sql/01_start.sql) создает резервную таблицу для анализа исходных данных, [sql/02_ddl.sql](sql/02_ddl.sql) создает звезду. Рабочий поток не читает `mock_data` в PostgreSQL.

## Запуск

Нужны Docker с Compose v2, доступ в интернет для сборки Maven и минимум 6 ГБ свободной памяти.

```bash
docker compose up -d --build
docker compose logs -f jobmanager taskmanager
```

В `http://localhost:8081` должна появиться job `sales_stream` со статусом RUNNING. После этого отправить данные.

```bash
docker compose --profile send run --rm producer
docker compose run --rm producer python Scripts/verify.py
```

Вторая команда ожидает загрузку до 6 минут и сверяет контрольные значения. [Scripts/check.sql](Scripts/check.sql) содержит дополнительные SQL-проверки. PostgreSQL доступен на `localhost:5434`, база и пользователь `postgres`, пароль `postgres`.

Повторная отправка тех же CSV не должна менять число продаж.

```bash
docker compose --profile send run --rm producer
docker compose run --rm producer python Scripts/verify.py
```

Kafka, checkpoint и PostgreSQL сохраняются в именованных томах. Для ручного восстановления job из checkpoint нужно использовать его путь в Flink UI или CLI. Обычный запуск новой job начинает чтение с earliest, повторная доставка безопасна для неизменных исходных данных. Отредактированная продажа с прежним ключом не обновляет уже записанный факт.

## Проверки и ограничения

Проверены количество строк в каждом CSV, уникальность составного ключа и контрольные суммы. Java-код компилируется с зависимостями Flink 1.20.1 и Kafka connector 3.3.0-1.20. Контейнерный запуск и связь всех сервисов требуют проверки команд выше. Успешный локальный SQL-расчет не заменяет интеграционный запуск.

Параметры баз в compose предназначены для локальной лабораторной работы. Сервисы привязаны к localhost. Разные работы можно запускать по отдельности. Инициализационные SQL выполняются только на пустом томе PostgreSQL.

Остановить сервисы с сохранением данных можно командой `docker compose down`. Команда `docker compose down -v` удаляет учебные базы, очереди и состояние сервисов. Для запуска с нуля после удаления томов повторить шаги из раздела запуска.
